# Сборка плагина на GitHub — пошагово для новичка

Инструкция «с нуля»: от регистрации до готового zip, который можно распаковать
в OBS. Занимает ~20 минут, из них 10–20 минут — сама сборка на серверах GitHub.

Что понадобится: браузер, электронная почта, папка с исходниками
(`obs-chat-overlay`) на диске.

---

## 1. Регистрация

1. Открой <https://github.com> → **Sign up**.
2. Email → пароль → имя пользователя (латиницей, без пробелов) → код из письма.
3. План — **Free** (бесплатный). Для публичных репозиториев минуты сборки
   не ограничены.

Если аккаунт уже есть — **Sign in** и переходи к шагу 2.

## 2. Создать репозиторий

1. В правом верхнем углу — **+** → **New repository**.
2. Заполни:
   - **Repository name**: `obs-chat-overlay` (без пробелов);
   - **Description**: можно пусто;
   - **Public** — обязательно оставь публичным (проще и без лимитов);
   - **НЕ ставь** галочки `Add a README file`, `Add .gitignore`, `Choose a
     license` — они создадут лишние файлы.
3. **Create repository**.

Откроется страница «Quick setup» с подсказками про git. Git нам не нужен —
файлы загрузим через браузер.

## 3. Загрузить файлы ⚠️ самый важный шаг

1. На странице репозитория нажми ссылку **uploading an existing file**
   (или **Add file → Upload files**).
2. Открой в Проводнике папку `obs-chat-overlay` (та, где лежат `CMakeLists.txt`,
   `buildspec.json`, `src`, `data`, `docs`, `.github`).
3. **Выдели всё внутри папки** (`Ctrl+A`) и перетащи в область браузера.
   Перетаскивать нужно **содержимое**, а не саму папку `obs-chat-overlay` —
   иначе файлы окажутся внутри лишней вложенной папки и сборка не найдёт
   `CMakeLists.txt`.
4. Дождись, пока все файлы появятся в списке (должно быть ~24 файла в
   6 папках). Прокрути список и проверь, что есть:
   - `CMakeLists.txt`
   - `buildspec.json`
   - `src/…` (13 файлов)
   - `data/locale/en-US.ini`
   - `docs/VERIFY.md`
   - `.github/workflows/build-windows.yml` ← **без него сборка не запустится**
5. Внизу страницы — **Commit changes** (сообщение можно оставить
   `initial upload`). Подтверди.

### Как выглядит правильная структура

```
obs-chat-overlay/
├── CMakeLists.txt          ← в корне репозитория
├── buildspec.json
├── src/
├── data/locale/en-US.ini
├── docs/VERIFY.md
└── .github/workflows/build-windows.yml
```

Если на главной странице репозитория видишь папку `obs-chat-overlay` внутри
репозитория — значит, перетащил саму папку. Исправляется так: открой эту папку
в веб-интерфейсе, выдели всё и перенеси на уровень выше (либо удали и загрузи
заново по шагу 3).

### Если папка `.github` не загрузилась

Некоторые браузеры игнорируют папки, начинающиеся с точки. Проверь главную
страницу репозитория: если `.github` нет —

1. **Add file → Create new file**;
2. В поле имени введи целиком: `.github/workflows/build-windows.yml`
   (слэши создадут папки автоматически);
3. Открой этот файл на диске Блокнотом:
   `…\obs-chat-overlay\.github\workflows\build-windows.yml`,
   `Ctrl+A` → `Ctrl+C` → вставь в браузер;
4. **Commit changes**.

## 4. Включить Actions

1. Вкладка **Actions** (вверху репозитория).
2. Если появился баннер «Workflows aren’t being run on this repository» —
   нажми **I understand my workflows, go ahead and enable them**.
3. Сборка запускается **автоматически** после загрузки файлов (workflow
   реагирует на `push`). Обнови страницу, если запусков пока не видно.

## 5. Запустить сборку (если не запустилась сама)

1. Вкладка **Actions** → в левом списке выбери **build**.
2. Справа кнопка **Run workflow** → ветка `main` → **Run workflow**.
3. Через несколько секунд появится запуск с жёлтым кружком.

## 6. Наблюдать за сборкой

1. Кликни по запуску → слева работа **windows-x64** → шаги:
   - `Fetch OBS plugin build scaffolding` — 5–20 сек;
   - **`Configure`** — самый долгий, 5–15 минут: скачиваются исходники OBS
     и `obs-deps`, собирается libobs;
   - `Build` — 1–3 минуты;
   - `Install`, `Package`, `upload-artifact`.
2. Итог: зелёная галочка ✅ и внизу страницы блок **Artifacts**.

**Если красный крест ❌**: кликни на упавший шаг → раскрой строки с ошибкой →
скопируй 40–60 строк, где есть `error C…`, `CMake Error`, `error MSB…`.
Пришли мне этот текст (или скачай полный лог: справа сверху **⋯ → Download
log**).

## 7. Скачать готовый плагин

1. Внизу страницы запуска — блок **Artifacts** → `obs-chat-overlay-windows-x64`.
2. Скачается один zip. Внутри — две папки: `obs-plugins/` и `data/`.
3. Распакуй его (правый клик → **Извлечь всё**).

Артефакты хранятся 90 дней, скачивание доступно только после входа в аккаунт.

## 8. Установить в OBS

1. Найди папку OBS: правый клик по ярлыку OBS → **Расположение файла**;
   обычно `C:\Program Files\obs-studio`.
2. Скопируй из распакованного архива папки `obs-plugins` и `data` в папку OBS
   с заменой файлов. Windows запросит подтверждение администратора — **Да**.
3. Полностью закрой и снова открой OBS.

Проверка: `Справка → Файлы журнала → Посмотреть текущий журнал`, должна быть
строка `[chat-overlay] loaded, source id obs_chat_overlay`.

Дальше — по чек-листу [docs/VERIFY.md](VERIFY.md): добавление источника,
настройки, ожидаемые строки лога.

## 9. Частые проблемы

| Симптом | Причина и решение |
| --- | --- |
| Нет вкладки Actions / пусто | не загрузился `.github/workflows/build-windows.yml` (шаг 3b) |
| «Workflows aren’t being run…» | нажать кнопку включения (шаг 4) |
| `Invalid workflow file` | YAML при копировании побился: проверь отступы (2 пробела), не должно быть табов |
| Нет кнопки **Run workflow** | workflow должен лежать в ветке `main`; проверь, что не в другой ветке |
| Сборка падает на `Configure` | чаще всего сетевой сбой при скачивании obs-deps; перезапусти workflow ( **Re-run all jobs** ) |
| Артефакт не скачивается | нужно быть залогиненным; истёк срок (90 дней) |
| В OBS нет источника | DLL не в `obs-plugins\64bit` или OBS не перезапущен; проверь лог |

## 10. Если нужно поменять код

1. Открой файл в репозитории → карандаш (**Edit**) → правки →
   **Commit changes**.
2. Сборка запустится автоматически, новый артефакт появится через ~15 минут.

Для правок в нескольких файлах удобнее вкладка **Code → Add file → Upload
files** (перезаписывает одноимённые файлы).
