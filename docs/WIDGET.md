# Виджеты StreamElements (HTML/CSS/JS)

Режим **«Виджет (HTML/CSS/JS)»** позволяет запускать в плагине почти любой
кастомный виджет из StreamElements: HTML, CSS, JS и настройки берутся из файлов
виджета, а сообщения чата передаются в него в том же формате, что и в
StreamElements.

## Как это работает

```
Twitch IRC ──► плагин ──► локальный HTTP-сервер (127.0.0.1)
                              │  /          — собранная страница
                              │  /events    — поток событий (SSE)
                              ▼
                    встроенный Browser Source в OBS
                    (html + css + js из файлов виджета)
```

Плагин собирает из ваших файлов одну страницу, отдаёт её встроенному
браузеру OBS и передаёт события:

- `onWidgetLoad` → `{ fieldData, data }` (значения из `fields.txt` и `data.txt`);
- `onEventReceived` → `{ listener: "message", event: { service: "twitch", data: {...} } }`
  с полями `nick`, `displayName`, `displayColor`, `text`, `emotes`, `badges`,
  `channel`, `isAction`, `time`.

Дополнительно подставляются заглушки `SE_API` (store/counters/sanitize), чтобы
виджет не падал на старте.

## Что даёт плагин виджету

| Что | Как |
| --- | --- |
| **animate.css** | подключается с CDN — нужен для классов вида `animate__fadeIn` / `animate__fadeOut`, которые используют большинство виджетов |
| **jQuery** | подключается с CDN (многие виджеты пишутся на нём) |
| **Смайлы Twitch** | `data.emotes` с `name`, `type`, `urls` (1/2/4) |
| **Смайлы BTTV и 7TV** | распознаются по словам и добавляются в `data.emotes` с прямыми ссылками на CDN |
| **Бейджи** | `data.badges` (set/version) плюс `data.badgeUrls` с готовыми картинками |
| **Консоль страницы** | `console.log/warn/error`, ошибки JS и `unhandledrejection` уходят в лог OBS как `[chat-overlay] widget console: ...` — это главный инструмент диагностики виджета |

Благодаря мосту консоли можно увидеть, что именно ломается внутри виджета:
например, если он сам обращается к `api.streamelements.com` и получает отказ.

## Как включить

1. Выгрузите файлы виджета из редактора StreamElements: `html.txt`, `css.txt`,
   `js.txt`, `fields.txt`, `data.txt`.
2. Положите их в одну папку, например `C:\obs-widgets\chat\`.
3. В OBS: свойства источника → **Виджет (HTML/CSS/JS)** →
   включите **«Запускать HTML/CSS/JS виджет»** → **Папка виджета** → выберите
   эту папку → **Применить**.
4. В логе появится:

   ```
   [chat-overlay] widget hosted at http://127.0.0.1:PORT/?v=... (viewers: 0)
   [chat-overlay] widget viewers: 1
   ```

   `viewers: 0` дольше нескольких секунд — значит браузерный источник не смог
   открыть страницу (см. ниже).

Изменения в файлах подхватываются автоматически: плагин следит за их временем
изменения и перезагружает страницу примерно через 2 секунды после сохранения.

## Какие имена файлов понимаются

| Назначение | Имена |
| --- | --- |
| HTML | `html.txt`, `index.html`, `widget.html` |
| CSS | `css.txt`, `style.css`, `widget.css` |
| JS | `js.txt`, `widget.js`, `script.js` |
| Поля | `fields.txt`, `fields.json` |
| Данные | `data.txt`, `data.json` |

Достаточно, чтобы присутствовал хотя бы один из html/css/js.

## Редактирование параметров виджета в OBS

Если у виджета есть `fields.txt`, плагин строит из него группу
**«Параметры виджета»** в свойствах источника:

| Тип поля в `fields.txt` | Контрол в OBS |
| --- | --- |
| `colorpicker` | выбор цвета с альфой |
| `checkbox` | галочка |
| `dropdown` | выпадающий список |
| `number` | целое число |
| `text` | строка |

Правила:

- значения по умолчанию берутся из `data.txt` (и `value` в `fields.txt`);
- пока поле не тронуто, виджет использует значение из файла — правки файлов
  продолжают работать;
- как только поле изменено, его значение хранится в настройках источника и
  перекрывает файлы; цветá переводятся в CSS `rgba(...)`;
- изменения применяются к виджету по кнопке **Применить** (страница
  перезагружается автоматически);
- `button` и `hidden` поля в интерфейс не попадают.

## Насколько точно выглядит как в StreamElements

Виджет получает ту же самую разметку, CSS и JS, поэтому вёрстка, шрифты,
отступы и анимации воспроизводятся им самим, а не плагином. Что важно знать:

| Что | Как ведёт себя |
| --- | --- |
| **Подстановки `{field}`** | CSS/HTML/JS виджета содержат плейсхолдеры вида `{namecol}`; плагин подставляет значения из `data.txt` (и `fields.txt`), иначе цветá и фон просто не применялись бы |
| **Шрифты** | `@import` на Google Fonts (Comfortaa) из CSS виджета; нужен интернет, иначе системный fallback |
| **Анимации** | классы `animate__*` + собственные keyframes виджета (sway, blink, pulse). animate.css грузится с CDN, плюс встроен локальный fallback на fadeIn/fadeOut/zoomIn |
| **Размер** | вёрстка в фиксированных px под 1920×1080. Держите «Ширина/Высота источника» = 1920×1080, иначе масштаб будет не тот |
| **Сообщения** | `onEventReceived` с `listener: "message"`, включая смайлы и бейджи |
| **Алерты follow/sub/tip/raid** | **не поддерживаются**: плагин отдаёт только сообщения чата, поэтому блоки `.alert` (котик, сердечко) не появляются |
| **Кнопки «Test message» в полях** | это внутренние кнопки StreamElements; в плагине они не нажимаются |

Дизайн рассчитан на тёмную сцену: цвета по умолчанию — `#fefdfd` для текста и
ника, фон сообщения `rgba(0,0,0,0.15)`, тени `#FFA1D4`. Эти значения берутся
из `data.txt`, так что менять их лучше там (или через поля в SE, затем снова
выгрузить файлы).

- Нужен **obs-browser** (входит в OBS). Если его нет, плагин пишет предупреждение
  и продолжает работать в нативном режиме.
- `jQuery` подключается с CDN (`code.jquery.com`); если нужен полностью офлайн —
  скажите, добавим настройку локального пути.
- Настройки «Внешнего вида» и пресеты тем в режиме виджета **не применяются**:
  весь дизайн задаёт виджет.
- Модерация плагина (команды, ссылки, капс, стоп-слова) работает и здесь —
  отфильтрованные сообщения в виджет не попадают.
- Это устройство эмуляции, а не сам StreamElements: события `follower`,
  `subscriber`, `cheer`, `raid` плагин не получает (только сообщения чата).
- Размер области виджета = «Ширина источника» × «Высота источника».
- Демо-режим тоже работает в виджете — удобно проверять оформление без сети.

## Диагностика

| Симптом | Что смотреть |
| --- | --- |
| `widget mode unavailable ...` | нет obs-browser или неверная папка |
| `widget viewers: 0` идёт долго | страница ещё грузится. CEF на слабом ноутбуке стартует 10–30 с; плагин в это время показывает нативный рендер, а сообщения копит в буфере и отправляет их, когда страница подключится |
| `widget page still has not connected ... after 30 s` | сервер работает, но браузер не открыл адрес. Проверьте: (1) открывается ли URL из лога в обычном браузере; (2) не мешает ли системный прокси/VPN — CEF использует системные настройки прокси |
| `chrome-error://chromewebdata` в логе | CEF не смог открыть страницу (чаще всего прокси или сервер был закрыт). Начиная с 1.1.7 плагин больше не закрывает сервер по таймауту |
| виджет пустой, но `viewers: 1` | виджет ждёт другие события (не `message`) или ошибку в JS — смотрите строки `[obs-browser: ...]` и `[chat-overlay] widget console:` |
| сообщения не появляются | проверьте, что виджет слушает `onEventReceived` с `listener: "message"` |
